# Watch CRM

Внутренняя CRM-система с интерфейсом в стиле старого Apple Watch: тёмная тема, круглые карточки, мягкие тени и быстрый доступ к компаниям.

## Стек
- Frontend: React + Vite
- Backend: Node.js + Express
- База данных: PostgreSQL
- Авторизация: JWT, пароль хранится в хешированном виде (scrypt)

## Возможности
- Вход по логину/паролю (`admin` / `admin`)
- Список компаний в виде круглых иконок
- Поиск по компаниям и фильтрация по статусу сделки
- Быстрый просмотр карточки компании
- Создание новой компании
- Страница компании: основная информация, контакты, заметки, задачи, история действий
- Логирование всех изменений в `activities`
- Подготовленная роль пользователя (`users.role`) для расширения прав доступа

## Запуск
1. Скопируйте переменные окружения:
   ```bash
   cp .env.example .env
   ```
2. Установите зависимости:
   ```bash
   npm install
   ```
3. Поднимите PostgreSQL:
   ```bash
   docker compose up -d
   ```
4. Запустите backend + frontend:
   ```bash
   npm run dev
   ```

- Frontend: http://localhost:5173
- Backend: http://localhost:4000/api


## Важно про авторизацию

### Если Docker не установлен (как у вас на macOS)
Проект теперь умеет запускаться **без PostgreSQL**: backend автоматически включает in-memory режим, если не может подключиться к БД.

Что это значит:
- Вы сможете войти в CRM (`admin/admin`) и протестировать весь интерфейс без Docker.
- Данные будут храниться только в памяти процесса и сбросятся после перезапуска backend.

Чтобы включился in-memory режим, достаточно просто запустить:
```bash
npm run dev
```
и убедиться в логе backend, что написано: `PostgreSQL недоступен, включён in-memory fallback`.

- Frontend ходит в API через относительный путь `/api` и Vite proxy на `http://localhost:4000`.
- Перед входом убедитесь, что backend действительно запущен (`npm run dev` из корня запускает оба сервиса).
- Если видите ошибку `Backend недоступен...`, проверьте порт `4000` и что процесс backend не упал.
